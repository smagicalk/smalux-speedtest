让每个节点都测得有序、可比较

Smalux Speedtest 将代理配置导入、分布式 Client 执行、实时进度和 PNG 报告集中在一个 Server 控制台中。Server 不保存原始订阅和 sing-box outbound。

Server + Client

Server 下发任务，Client 在各地执行测速并回传结果。

协议 v2 调度

单 Client 单工作单元，同一代理全局排他，完整保留矩阵。

隐私优先

代理凭据只驻留内存，日志和历史结果不包含敏感连接数据。

快速开始

Server 和 Client 必须使用同一协议版本。Client 需要使用 with_utls 构建，否则 Reality/uTLS 节点无法初始化。

构建

make build

# Windows Client
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 \
  go build -buildvcs=false -tags with_utls \
  -o dist/smalux-client-windows-amd64.exe ./client

启动 Server

SMALUX_ADMIN_PASSWORD='change-this-password' \
  ./dist/smalux-server-linux-amd64 \
  -listen 0.0.0.0:8080 \
  -db /var/lib/smalux/smalux.db

首次启动默认管理员为 admin。登录控制台后创建 Client。Token 只显示一次，请通过环境变量注入 Client 进程。

启动 Client

SMALUX_CLIENT_TOKEN='CLIENT_TOKEN' \
  ./dist/smalux-client-linux-amd64 \
  -server wss://speed.example.com/ws/client
临时明文连接：只有在可信内网测试时才启用 Server 的 -allow-insecure-ws。公网部署必须使用 HTTPS/WSS，否则 Token 和测速任务会被网络路径看到。

一键安装服务

Linux 主机可以使用仓库中的 scripts/smalux.sh。脚本从最新 GitHub Release 下载对应架构包并校验 SHA256，然后交互式创建 systemd 服务。

curl -fsSL https://raw.githubusercontent.com/smagicalk/smalux-speedtest/main/scripts/smalux.sh -o smalux.sh
chmod +x smalux.sh
sudo ./smalux.sh

# 非交互子命令
sudo ./smalux.sh update
sudo ./smalux.sh status
sudo ./smalux.sh uninstall

架构

模块职责
server / internal/serverappHTTP 控制台、管理员认证、任务状态、WebSocket Hub、SSE 进度和报告导出。
client / internal/clientapp认证连接、接收工作单元、启动 sing-box outbound、延迟/上下行测速。
internal/importer解析单条 URI、批量文本、订阅内容和可选 Base64，归一化为 sing-box 配置。
internal/storeSQLite 持久化管理员、Client 元数据、任务状态和脱敏结果。
internal/telegrambot可选 Telegram Bot，负责授权、交互式任务创建和 PNG 回复。

完整 outbound 只存在于 Server 的运行时任务内存和当前 Client 进程内。任务结束、取消或超时后，服务会清理内存中的代理字节。

协议 v2 调度规则

调度器把一个批次拆成多个单代理工作单元，每个工作单元都有唯一 WorkID。Server 为 Client 和代理 outbound 同时建立内存 lease。

  • 一个 Client 同时最多执行一个工作单元，避免本地带宽和 CPU 互相干扰。
  • 相同 outbound 的代理在所有活动任务之间全局排他，不会被两个 Client 同时测速。
  • 空闲 Client 会立即领取当前未锁定节点；不同节点仍可以在不同 Client 上并行。
  • 每个选中的 Client 最终都会测试每个代理，结果仍是完整的 Client × 节点矩阵。
  • 完成、失败、取消、超时、撤销 Token、断线和重连都会释放或重建 lease。
升级要求：协议版本从 v1 升级到 v2 后，Server 和所有 Client 必须一起更新。旧 Client 会因版本或工作单元校验失败而拒绝连接。

代理与测速任务

网页端支持单条、批量文本和订阅导入，订阅内容可额外使用 Base64。支持的协议包括 Shadowsocks、VMess、VLESS、Trojan、SOCKS5、HTTP、SSH、AnyTLS、Hysteria、Hysteria2 和 TUIC。

任务参数包括候选测速节点数量、Top N 下载/上传节点和线程数。每个 Client 的任务参数由 Server 下发，Client 命令不需要重复配置这些选项。

任务详情页提供实时 SSE 进度、结果表格、CSV 和品牌化 PNG 报告。Bot 创建的任务会编辑同一条进度消息，并在完成后引用原始请求回复图片。

Telegram Bot（可选）

Bot 默认关闭。最高权限管理员在网页的系统设置中绑定 Token 和 Telegram Owner ID，网页会通过验证码确认绑定，不需要把 Bot Token 写入启动命令。

  • 启动后自动注册 Bot 菜单和 inline 按钮。
  • 逐步选择代理内容、Client、候选节点、Top N 和线程数。
  • Client 支持分页和多选，已选择项使用绿色实心方块标识，未选择项使用空心方块。
  • 只有 Owner 可以授权或撤销 Telegram 用户；普通授权用户只能提交自己的测速任务。
  • Bot Token 使用本地密钥加密保存，日志不输出 Token、消息正文、代理地址或用户 IP。
命令用途
/id查看 Telegram 用户和会话 ID。
/authorize USER_IDOwner 授权用户。
/revoke USER_IDOwner 撤销用户。
/test PROXY_TEXT提交单条、批量或 Base64 代理内容。
/sub URL获取 HTTP(S) 订阅并创建测速任务。

安全与隐私

  • Client Token 只保存哈希；网页创建后只显示一次明文 Token。
  • 原始订阅 URL、订阅正文、sing-box outbound、代理密码和私钥不写入 SQLite。
  • 历史结果只保留脱敏地址、节点名称、协议、测速节点和测量数据。
  • 日志使用固定错误类别，不输出代理配置、请求正文、远端地址和数据库路径。
  • 管理员通过邀请码注册；每个管理员可以在账户安全页面修改自己的密码，改密会使其他会话立即失效。

安全边界不能替代网络加密。公共服务建议使用同机 HTTPS/WSS 反向代理，并限制管理控制台访问来源。

构建与发布

.github/workflows/release.yml 支持三种入口：

  • 推送 main：运行测试并上传六个平台包作为 Actions Artifact。
  • 推送 v* Tag：运行测试、编译六个平台、生成 SHA256SUMS 并上传 GitHub Release。
  • 手动触发：通过下拉框选择 vibe-dev 或 main、系统、架构和版本，只编译所选的一个目标并保留为测试 Artifact。
# 手动验证当前分支的交叉编译
gh workflow run "Build And Release" \
  --ref vibe-dev \
  -f ref=vibe-dev \
  -f os=windows \
  -f arch=amd64 \
  -f version=dev

# 正式发布
git tag v1.0.0
git push origin v1.0.0
