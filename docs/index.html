Smalux Speedtest 将代理配置导入、分布式 Client 执行、实时进度和 PNG 报告集中在一个 Server 控制台中。Server 不保存原始订阅和 sing-box outbound。

Server + Client

Server 下发任务，Client 在各地执行测速并回传结果。

协议 v2 调度

单 Client 单工作单元，同一代理全局排他，完整保留矩阵。

隐私优先

代理凭据只驻留内存，日志和历史结果不包含敏感连接数据。

快速开始

Server 和 Client 必须使用同一协议版本。Client 需要使用 with_utls 构建，否则 Reality/uTLS 节点无法初始化。

构建

make build

# Windows Client
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 \
  go build -buildvcs=false -tags with_utls \
  -o dist/smalux-client-windows-amd64.exe ./client

启动 Server

SMALUX_ADMIN_PASSWORD='change-this-password' \
  ./dist/smalux-server-linux-amd64 \
  -listen 0.0.0.0:8080 \
  -db /var/lib/smalux/smalux.db

首次启动默认管理员为 admin。登录控制台后创建 Client。Token 只显示一次，请通过环境变量注入 Client 进程。

启动 Client

SMALUX_CLIENT_TOKEN='CLIENT_TOKEN' \
  ./dist/smalux-client-linux-amd64 \
  -server wss://speed.example.com/ws/client
临时明文连接：只有在可信内网测试时才启用 Server 的 -allow-insecure-ws。公网部署必须使用 HTTPS/WSS，否则 Token 和测速任务会被网络路径看到。

一键安装服务

Linux 主机可以使用仓库中的 scripts/smalux.sh。脚本从最新 GitHub Release 下载对应架构包并校验 SHA256，然后交互式创建 systemd 服务。

curl -fsSL https://raw.githubusercontent.com/smagicalk/smalux-speedtest/main/scripts/smalux.sh -o smalux.sh
chmod +x smalux.sh
sudo ./smalux.sh

# 非交互子命令
sudo ./smalux.sh update
sudo ./smalux.sh status
sudo ./smalux.sh uninstall

开发架构

项目是单 Go module、两个进程入口。Server 负责控制面、调度和持久化，Client 负责数据面执行。浏览器和 Telegram 只是两个任务入口，最终都进入同一个 serverapp.startTask，因此参数校验、订阅安全、调度语义和隐私边界不会分叉。

最重要的边界：SQLite 中只有任务摘要、目标状态和脱敏结果。分享链接、订阅正文和 sing-box outbound 只在 runtimeTask.assignment 与当前 Client 执行上下文中短暂存在。

依赖方向

入口包只做配置和生命周期；业务包依赖共享模型与 Store，不反向依赖可执行入口。新增能力时应尽量沿用以下方向，避免把 HTTP、Telegram 或 SQLite 细节带进 Client 执行器。

server/main -> serverapp -> store / subscription / importer / model / wire
client/main -> clientapp -> importer-produced model / wire / sing-box
telegrambot <- serverapp adapter -> shared task service
web browser <- JSON + SSE API -> serverapp

详细调用流程

1. Server 启动与关闭

  1. server/main.go读取命令行和 SMALUX_* 环境变量，建立根 Context、结构化日志和信号处理。
  2. serverapp.New调用 store.Open；Store 打开单连接 SQLite，设置 WAL、foreign keys、busy timeout，并执行全部幂等迁移和隐私清洗。
  3. 管理员引导通过 BootstrapAdmin 创建首次 Owner；已有数据库不会再次使用启动密码覆盖账户。
  4. 组件装配创建 Hub、SSRF Fetcher、Session Store、模板和可选 Telegram 控制器，再注册 routes()。
  5. Run启动 HTTP Server；Client WebSocket、管理 API、静态资源与健康检查共用该监听器。
  6. Shutdown先阻止新工作并停止 Bot，再终结/清理 Hub 运行态、关闭 HTTP 与数据库。重启无法恢复包含代理凭据的活动任务，迁移会把遗留 queued/running 标记为 failed。

2. 网页创建任务

  1. 浏览器从 dashboard.html 取得 Session 对应的 CSRF Token，dashboard.js 向 POST /api/tasks 提交来源、Client ID 和三个有界参数。
  2. requireAdmin + csrf验证会话、账户启用状态和同步 Token；createTask 再确认普通管理员只能使用自己创建的 Client。
  3. startTask先检查目标非空。存在订阅 URL 时调用 subscription.Fetcher，每次 DNS、连接和重定向都重新执行 SSRF 防护。
  4. importer.Parse识别普通文本或整体 Base64，逐行转换为 model.ProxySpec，按规范键去重。无效行只形成脱敏 ImportError。
  5. 服务校验应用默认 Candidate=10、Top N=3、Threads=4，验证范围、Client 存在/启用状态和去重后的目标顺序。
  6. wire 预检对每个单代理工作单元构造真实 task.assign Envelope，确保编码后不超过 2 MiB。失败发生在数据库写入之前。
  7. store.CreateTask在一个事务中写入任务摘要和全部 task_targets；只保存成功数、跳过数和创建管理员 ID，不保存导入正文。
  8. hub.AddTask把完整 Assignment 放入内存，计算临时 HMAC 代理指纹，建立 per-Client 工作顺序并触发全局调度。

3. Hub 分配与 Client 执行

  1. 连接握手Client 用 Bearer Token 升级 WebSocket，10 秒内发送 client.hello；Server 验证协议 v2 后返回 server.welcome，才把 peer 暴露给调度器。
  2. reserveNextWork按任务轮转和目标顺序选择空闲 Client、未完成代理，同时取得 Client lease 与代理指纹 lease。
  3. task.assign只携带一个代理、稳定 TaskID、新 WorkID、代理位置和测速参数。发送失败会回滚 reservation 并继续调度其他可用 Client。
  4. Client worker验证 Assignment，建立 600 秒任务 Context，发送 task.ack，然后调用 Executor。
  5. Executor为该代理启动独立 sing-box outbound，通过其 DialContext 请求 Speedtest 配置，先测候选延迟，再对 Top N 执行下载和上传。
  6. 进度与结果Client 按阶段发送 task.progress，每个 Speedtest 节点发送一条 task.result，最后发送 task.complete；异常则发送固定类别的 task.failed。

4. 结果落库与页面实时更新

  1. 不信任回传Hub 使用当前 WorkID、Client peer 和 Assignment 快照重建代理/Client 身份，限制进度范围，并归一化协议、名称、测速节点与错误类别。
  2. 幂等结果写入store.SaveResult以 Task + Client + Proxy + Speed Server 为唯一键写入脱敏结果，重复回传执行更新而非追加。
  3. 目标事务FinishTarget原子更新一个 task_target 并聚合父任务；全部目标终结后确定 completed、partial 或 failed。
  4. SSEHub 发布 progress、result、target 和 status。慢浏览器队列满时允许丢增量，不能反压测速主流程。
  5. REST 兜底task.js用 revision 合并 SSE 与 GET /api/tasks/{id} 快照，避免旧 HTTP 响应覆盖新结果/target 状态，并每 12 秒低频复核。
  6. 报告CSV 由 Server 从持久化结果生成；网页 PNG 在浏览器 Canvas 中生成；Telegram PNG 使用 internal/reportpng。

5. 断线、取消、撤销与超时

事件处理流程最终效果
Client 断线/连接替换unregister/register -> requeueTarget；运行目标数据库回到 queued，释放当前工作和两个 lease，发布 target SSE。有效 Token 重连后只继续该 Client 尚未完成的代理。
管理员取消POST .../cancel -> Hub.CancelTask -> store.CancelTask，再向在线 peer 发送 task.cancel。活动目标变 canceled，敏感 Assignment 清理，结果保留。
Client Token 撤销先禁用数据库凭据，再从 Hub 移除连接并对活动目标调用 finishTarget(...failed)。旧连接关闭，后续认证拒绝，其他 Client 可继续。
10 分钟任务到期expireTask设置 terminalPending，在事务中失败化全部活动目标；数据库忙时有界重试。任务 failed，并尽力通知 Client 停止本地流量。
Server 重启内存 Assignment 不恢复；启动迁移扫描遗留活动任务和目标。统一标记 failed，避免永久 queued/running。

状态模型与应用层协议

开发状态机时必须区分“数据库公开状态”和“Hub 仅内存状态”。assigned、lease、WorkID、代理指纹和 outbound 都是进程内实现细节，不应新增到 SQLite。

任务状态

queued -> running -> completed
                  \-> partial
                  \-> failed
queued/running ----> canceled
queued/running ----> failed (timeout/restart)

目标 Client 状态

queued -> running -> completed
   ^          |----> failed
   |          |----> canceled
   +----------+
    disconnect/replacement

Hub 内部还会短暂使用 assigned 表示消息已发送但尚未 ACK；数据库在 ACK 成功前仍保持 queued。

浏览器 SSE 事件

协议 v2 调度规则

调度器把一个批次拆成多个单代理工作单元，每个工作单元都有唯一 WorkID。Server 为 Client 和代理 outbound 同时建立内存 lease。

  • 一个 Client 同时最多执行一个工作单元，避免本地带宽和 CPU 互相干扰。
  • 相同 outbound 的代理在所有活动任务之间全局排他，不会被两个 Client 同时测速。
  • 空闲 Client 会立即领取当前未锁定节点；不同节点仍可以在不同 Client 上并行。
  • 每个选中的 Client 最终都会测试每个代理，结果仍是完整的 Client × 节点矩阵。
  • 完成、失败、取消、超时、撤销 Token、断线和重连都会释放或重建 lease。
升级要求：协议版本从 v1 升级到 v2 后，Server 和所有 Client 必须一起更新。旧 Client 会因版本或工作单元校验失败而拒绝连接。

代理与测速任务

网页端支持单条、批量文本和订阅导入，订阅正文可额外使用 Base64。导入器和正式 Client 当前支持以下 11 类分享链接：

协议URI / 格式已支持能力
Shadowsocksss://SIP002 Base64、明文百分号转义、旧式整段 Base64 和插件参数。
VMessvmess://Base64(JSON)加密方式、alter ID、packet encoding、TLS/uTLS 和 V2Ray transport。
VLESSvless://Flow、packet encoding、TLS/uTLS、Reality 和 V2Ray transport。
Trojantrojan://默认启用 TLS，支持 TLS/uTLS 和 V2Ray transport。
SOCKS5socks://、socks5://可选用户名和密码；两种 scheme 均转换为 SOCKS5。
HTTP 代理http://、https://可选用户名和密码；HTTPS 表示连接上游代理时启用 TLS。
SSHssh://用户名和密码认证。
AnyTLSanytls://密码认证和强制 TLS。
Hysteria v1hysteria://认证、必填上下行带宽、XPlus 混淆、TLS 和端口跳跃。
Hysteria2hysteria2://、hy2://密码、可选带宽、Salamander 类混淆、TLS 和端口跳跃。
TUICtuic://UUID/密码、TLS、拥塞控制和 UDP relay mode。

VMess、VLESS 和 Trojan 的 V2Ray transport 支持默认 TCP（省略或使用 tcp、raw、none）、WebSocket、gRPC、HTTP/H2 和 HTTPUpgrade。其他 transport 会在导入阶段被拒绝，不会静默退化成 TCP；正式 Client 当前不启用 KCP 和 V2Ray QUIC。这不影响使用独立原生 QUIC 实现的 Hysteria、Hysteria2 与 TUIC。

不支持：SSR 已被 sing-box 1.13 移除；Naive 会引入体积较大的多平台 Cronet 运行库，因此项目有意不注册。其他未列出的 URI 会返回协议不支持。

任务参数包括候选测速节点数量、Top N 下载/上传节点和线程数。每个 Client 的任务参数由 Server 下发，Client 命令不需要重复配置这些选项。

任务详情页提供实时 SSE 进度、每个目标 Client 的执行状态、结果表格、CSV 和品牌化 PNG 报告。存在无效代理行时只展示成功与跳过数量，不持久化原始输入或导入明细。Bot 创建的任务会编辑同一条进度消息，并在完成后引用原始请求回复图片。

二次开发指南

先确定变化属于哪一条边界，再从边界两侧同时修改。仅让代码“能够编译”通常不够：wire 变化涉及 Server 与 Client，持久化变化涉及迁移与隐私，任务变化涉及网页与 Telegram 两个入口。

常见扩展的修改落点

需求至少检查的代码与兼容要求
新增代理分享协议在 internal/importer 增加 scheme 解析、规范化和测试，并在 internal/clientapp/singbox.go 注册对应 sing-box outbound。确认目标平台依赖、构建标签和二进制体积后，再更新支持列表。
增加测速参数贯穿 taskRequest、参数校验、store.Task、model.Assignment、Dashboard、Telegram 向导和 Executor。参数需要明确默认值、上下限及旧数据库默认值。
修改 WebSocket 消息先改 internal/model 与 internal/wire，再同步 Hub 和 Client。任何不兼容的字段语义、消息顺序或尺寸变化都应提升 model.ProtocolVersion，并要求 Server/Client 同步升级。
新增数据库字段在 internal/store/migration.go 中为新库更新建表语句，并通过 ensureColumn 为旧库做幂等迁移；同步 Scan、INSERT/UPDATE、公开结构和升级测试。不要把代理凭据加入 schema。
新增管理 API在 serverapp.routes 显式声明方法和路径；读取接口套 requireAdmin，写接口再套 csrf，Owner-only 操作增加 requireOwner。资源查询后仍需执行对象归属校验。
修改任务详情 UIHTML/CSS/ES module 位于 internal/serverapp/web。实时字段同时处理 SSE 增量和 REST 快照，并考虑旧快照晚到的覆盖竞态。资源由 go:embed 打包，修改后必须重启重新构建的 Server。
修改调度策略从 hub_dispatch.go 的 reservation/lease 入手，并检查 ACK、完成、失败、取消、到期、撤销、断线、连接替换和 Shutdown 的释放路径。状态变更必须遵守 transition 锁和“先落库、后发布”原则。
增加 Telegram 交互internal/telegrambot 负责 API 与更新解析，internal/serverapp/telegram*.go 负责授权和任务适配。测速创建必须复用 startTask，不要建立另一套导入或调度逻辑。
修改报告字段同步 CSV、浏览器 report.js 与 Server internal/reportpng。机器导出可保留稳定英文枚举，界面和图片在展示层本地化。

/api/tasks/{id}/events归属校验后的 SSE 长连接；只提供实时提示，REST/SQLite 才是可恢复的权威状态。
/ws/clientBearer Client Token，不使用管理员 Session 或 CSRF；默认要求 HTTPS/WSS，并在升级后执行 v2 hello/welcome 握手。
/healthz、/static/*公开健康检查和嵌入资源；不得携带运行配置或敏感诊断信息。

必须保持的工程约束

  • 输入不可信：浏览器、Telegram、订阅服务和已持有 Token 的 Client 都是外部输入。身份字段应由服务端上下文重建，文本、数值、数量和消息大小必须有界。
  • 敏感数据只驻留内存：分享链接、订阅正文和 outbound 不进入数据库、日志、SSE、报告或任意错误文本；任务终结时继续调用现有清理路径。
  • SQLite 先于事件：终态先成功提交，再移除 runtime、清理凭据并发布 SSE。数据库暂时失败时保留不可继续执行的内存状态并有界重试。
  • 并发 I/O 不持有 Hub 全局锁：在锁内只快照/提交内存决定，WebSocket 与 SQLite I/O 放到锁外或使用任务级 transition 串行化。
  • 事件可丢，结果不可丢：Progress/SSE 可以尽力而为；Result 与终态发送失败必须断开连接，由服务端重排与幂等键保证收敛。
  • 兼容升级可重复：迁移要能在每次启动执行，协议不兼容要显式升版本，错误类别和 CSV 字段应保持机器稳定。

推荐实现顺序

  1. 先写领域模型、状态转换或导入器的单元测试，固定新行为和失败边界。
  2. 实现 Store/Client 等内层能力，再接入 Hub 或共享任务服务。
  3. 接入 HTTP 与 Telegram 适配层，补权限、CSRF、正文上限和安全错误映射。
  4. 最后接 UI/SSE 展示，并用真实 Server/Client 流程验证断线和终态。
  5. 完成普通测试、发布标签测试、race、vet、构建和文档同步后再提交。

定位一条任务

  1. 先看持久化快照：任务详情 REST 返回 task、targets 和 results，能区分“页面没更新”与“服务状态没推进”。
  2. 再看实时通道：浏览器 Network 中确认 SSE 是否连接并收到 target/status；Client 侧确认 WebSocket 是否完成 welcome、assign、ack。
  3. 按 WorkID 查竞态：TaskID 关联整批任务，WorkID 关联单个代理工作。迟到 ACK/result/complete 必须因 peer 或 WorkID 不匹配而被忽略。
  4. 检查目标而非只看父任务：父状态由所有 task_targets 聚合；单个 Client 断线、失败或取消通常先体现在 target。
  5. 避免打开敏感日志：不要为调试打印 Envelope payload、订阅正文或 outbound。使用 TaskID、WorkID、Client ID、固定错误类别和状态转换定位问题。
前端调试提示：Server 二进制嵌入 internal/serverapp/web。编辑 JS/HTML/CSS 后，旧进程不会自动读取磁盘文件；需要重新构建或重新 go run 并重启实例。

Telegram Bot（可选）

Bot 默认关闭。最高权限管理员在网页的系统设置中绑定 Token 和 Telegram Owner ID，网页会通过验证码确认绑定，不需要把 Bot Token 写入启动命令。

  • 启动后自动注册 Bot 菜单和 inline 按钮。
  • 逐步选择代理内容、Client、候选节点、Top N 和线程数。
  • Client 支持分页和多选，已选择项使用绿色实心方块标识，未选择项使用空心方块。
  • 只有 Owner 可以授权或撤销 Telegram 用户；普通授权用户只能提交自己的测速任务。
  • Bot Token 使用本地密钥加密保存，日志不输出 Token、消息正文、代理地址或用户 IP。
命令用途
/id查看 Telegram 用户和会话 ID。
/authorize USER_IDOwner 授权用户。
/revoke USER_IDOwner 撤销用户。
/test PROXY_TEXT提交单条、批量或 Base64 代理内容。
/sub URL获取 HTTP(S) 订阅并创建测速任务。

安全与隐私

  • Client Token 只保存哈希；网页创建后只显示一次明文 Token。
  • 原始订阅 URL、订阅正文、sing-box outbound、代理密码和私钥不写入 SQLite。
  • 历史结果只保留脱敏地址、节点名称、协议、测速节点和测量数据。
  • 日志使用固定错误类别，不输出代理配置、请求正文、远端地址和数据库路径。
  • 管理员通过邀请码注册；普通管理员只能查看和操作自己创建的任务，Owner 可以管理全部任务。
  • 每个管理员可以在账户安全页面修改自己的密码，改密会使其他会话立即失效。

安全边界不能替代网络加密。公共服务建议使用同机 HTTPS/WSS 反向代理，并限制管理控制台访问来源。
